# Wikidataと典拠管理の査読基準

このファイルは、記事全体、Wikidata由来の表示、言語間リンク、`Normdaten`、典拠識別子を査読するときに使う。ローカルの記事、Wikidata項目、展開テンプレート、外部の典拠レコードを別の層として確認する。

## 文書の位置付け

- [Wikipedia:ウィキデータ](https://ja.wikipedia.org/wiki/Wikipedia:ウィキデータ)は日本語版での利用を説明する解説である。
- [Wikipedia:典拠管理](https://ja.wikipedia.org/wiki/Wikipedia:典拠管理)は編集者向けの手引きである。
- [Template:Normdaten](https://ja.wikipedia.org/wiki/Template:Normdaten)の現行解説は、引数、取得対象、表示、追跡カテゴリの技術根拠とする。
- これらは内容方針や出典要件を置き換えない。Wikidataの値や典拠レコードへのリンクがあるだけで、Wikipedia本文の記述に信頼できる出典が付いたことにはならない。

## Wikidata項目の同一性

記事に`wikibase_item`がある場合、Q番号の存在だけで合格としない。次を確認する。

- 日本語版サイトリンクが査読対象の記事または意図したリダイレクトを指すか。
- 項目のラベル、別名、説明、`instance of`などが記事の主題と同じ実体を示すか。
- 同名人物、同名組織、作品とシリーズ、建物と運営組織、河川と水系、歴史上の実体と現行組織を混同していないか。
- 重複項目、誤った統合、別主題のサイトリンク、記事より広いまたは狭い範囲の項目でないか。
- 言語間リンク先が単に名前の似た記事ではなく、同じ主題と範囲を扱うか。

一致を判断できない場合は、ラベルだけで結論せず、各言語版の導入部、Wikidataの文、識別子、サイトリンクを照合して`要確認`とする。

## 記事へ表示される値

インフォボックス、地図、典拠管理などがWikidataから値を取得する場合、表示された各重要値について次を確認する。

- プロパティと値が記事の主題に対応しているか。
- 複数値、優先ランク、非推奨ランク、修飾子、適用時点、単位が表示の文脈に合うか。
- 古い値、将来値、別時点の値を「現在値」として表示していないか。
- Wikidata上の出典、参照URL、取得日があるか。ただし、それだけでWikipedia本文の出典要件を満たすとみなさない。
- ローカル引数がWikidata値を上書きしている場合、どちらが表示され、その選択に合理性があるか。
- Wikidata変更により記事の意味が変わる箇所を、版を固定せず断定しない。

記事の主張を直す根拠には、Wikidataではなく信頼できる情報源を用いる。Wikidataとの不一致は、記事、Wikidata、両方のどこが誤っているかを資料で判定する。

## `Normdaten`を使うべき場合

`Normdaten`は人物専用ではない。人物、組織、地名、作品、概念など、図書館、研究機関、音楽データベース等の典拠レコードと明確に対応する主題で利用できる。

全文査読では次を確認する。

1. 記事末尾に`{{Normdaten}}`または別名の`{{Authority control}}`があるか。
2. 対応するWikidata項目に、テンプレートが対応する典拠識別子があるか。
3. 識別子が記事の主題そのものを指し、同名別人、別組織、作品の別版、上位・下位概念を指していないか。
4. テンプレートの表示先を実際に開き、少なくとも主要識別子の名称、実体種別、代表的な書誌情報が一致するか。

対応識別子が存在し、典拠レコードへの導線が読者に有用なのにテンプレートがない場合は、通常`軽微`の改善案として追加を提案する。

現時点で対応識別子がなくても、人物、組織、地名、作品、概念など、将来典拠識別子がWikidataへ追加され得る明確な実体なら、引数なしの`{{Normdaten}}`を先行設置してよい。テンプレート解説は、識別子の有無を事前確認せず貼り付けても問題ないと明記している。全文査読では、このような主題にテンプレートがなければ、将来の識別子追加を自動反映する保守上の利点を示し、通常`軽微`の任意改善として追加を提案できる。

ただし、これは全記事への設置義務を定めた方針・ガイドラインではない。現時点で識別子がない場合、テンプレートは何も表示しないため、未設置や無表示それ自体を欠陥、方針違反、または査読不合格の理由にしない。曖昧さ回避、一覧、複数の実体を一括して扱う記事、主題と典拠項目が一対一に対応しない記事には機械的に追加せず、`additional`の要否を含めて対応関係を確認する。

## `Normdaten`の引数と依存関係

通常は引数なしの`{{Normdaten}}`を使い、識別子そのものはWikidataで管理する。次を点検する。

- `qid`: Wikidata項目に接続されていない利用者名前空間の下書き等で手動指定する。記事が項目に接続済みなら無視されるため、記事中の冗長または誤解を招く指定を確認する。
- `additional`: 複数実体を扱う記事で追加のQ番号から識別子を取得する。各項目が記事の対象範囲に含まれるかを一件ずつ確認する。`auto`の結果も無検証で受け入れない。
- `show`または別名`country`: 表示する識別子群を制限する。両方を同時指定せず、制限する理由と読者への影響を確認する。
- `suppress`: 特定プロパティの表示を抑制する。識別子が誤っているなら抑制だけで隠さず、Wikidata側の値と出典を確認する。正当な例外なら理由を記録する。
- `state`: 折り畳み状態だけを制御する。表示識別子が一分野だけの場合は無視されることがある。

典拠テンプレートは記事下部で、ナビゲーションテンプレートの後、スタブと`DEFAULTSORT`・カテゴリの前に置く。`Taxonbar`と併用するときは`Taxonbar`を上、`Normdaten`を下にする。

## エラーと追跡カテゴリ

`Normdaten`は識別子の形式を検査するが、形式が正しいことは実体の一致を保証しない。表示と実効カテゴリの両方を確認する。

- `Category:注意を要する典拠管理識別子があるページ`
- `Category:誤った典拠管理情報が指定されている記事`
- `Category:典拠管理で不明な引数を指定しているページ`
- `Category:抑制された典拠管理識別子がある記事`: 追跡用であり、それだけではエラーではない。

エラーがWikidata値に由来するのか、記事の`additional`、`show`、`suppress`等に由来するのか、共有モジュールに由来するのかを分ける。記事側の入力が正しければ、記事からテンプレートを外してエラーを隠す提案をしない。

## 報告

全文査読では次を示す。

| 項目 | 内容 |
| --- | --- |
| Wikidata | Q番号、サイトリンクと主題の一致、依存する重要プロパティ |
| 表示値 | ローカル値 / Wikidata値 / 上書き、時点、単位、未確認事項 |
| 典拠管理 | 必要性、テンプレート、引数、主要識別子の同一性 |
| 実効状態 | 表示、エラー、追跡カテゴリ、発生元 |

誤ったWikidata項目や識別子により別人・別組織等へリンクする場合は`中`以上を検討する。`Normdaten`の有用な追加、冗長な`qid`、配置だけの問題は通常`軽微`とする。
