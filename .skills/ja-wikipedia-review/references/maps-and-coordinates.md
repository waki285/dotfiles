# 地図、座標、Kartographerの査読基準

このファイルは、座標、地図、Kartographer、GeoJSON、KML、地図用テンプレートがある記事、または地理的主題の記事全体を査読するときに使う。地図が表示されるかだけでなく、どのデータ源が何を表しているかを確認する。

## 対象を棚卸しする

ソースと展開結果から次を探す。

- `{{Coord}}`、ウィキ座標系テンプレート、`display=title`、`name`、座標オプション。
- `{{Maplink}}`の現行リダイレクト先である`{{Maplink2}}`、`{{Mapriver}}`、`{{Infobox mapframe}}`、`{{座標一覧}}`。
- `Location map`、`OSM Location map`、`Attached KML`等の地図テンプレート。
- 生の`<mapframe>`、`<maplink>`、GeoJSON、Commonsの`Data:*.map`、KML。
- ページプロパティの`kartographer_frames`、Geoマイクロフォーマット、座標・Kartographer・OSM関係の追跡カテゴリ。

直接のタグやファイルリンクがなくても、テンプレート展開で地図が生成される。記事ソース、展開テンプレート、ページプロパティ、表示を照合する。

## 座標の内容を確認する

- 座標が記事の主題そのものを示すか。建物、入口、敷地中心、自治体中心、山頂、河口、流域、路線、運営組織を混同しない。
- 緯度と経度の順序、正負、`N/S/E/W`、度分秒と十進表記の対応を確認する。
- 国際地球基準座標系に準拠する情報を用い、実用上のWGS84との扱いは現行の[緯度・経度の調べ方](https://ja.wikipedia.org/wiki/Wikipedia:緯度・経度の調べ方)を確認する。
- 対象の大きさと情報源の精度を超える桁数を避ける。広い地域や線状対象を不合理な一点精度で示さない。
- 座標の根拠を、信頼できる地図、行政資料、施設資料等で確認する。他言語版やWikidataの値を無条件に転記しない。
- `region`、`type`、`scale`または`dim`、`globe`、`name`が対象と表示用途に合うか。
- `display=title`が複数競合していないか。複数地点の記事では、主座標と本文内座標を区別する。

`{{Coord}}`は可変長の名無し引数を使うため、TemplateDataだけでは十分に検証できない。現行の[Template:Coord](https://ja.wikipedia.org/wiki/Template:Coord)の例、表示、`Category:座標タグに誤りがあるページ`を併用する。

## Kartographerと地図の依存関係

地図ごとに供給元を特定する。

| 供給元 | 主な確認対象 |
| --- | --- |
| 記事ソース | 座標、GeoJSON、表示引数、ラベル、説明 |
| Wikidata | Q番号、P625、P402、P3896、主題との一致 |
| OpenStreetMap | Wikidataタグ、relation、線・面・点の実体、更新反映 |
| Commons | `Data:*.map`の存在、GeoJSON、データの対象、ライセンス、更新日 |
| KMLまたは外部ツール | 対象記事・節、リンク先、応答、件数制限 |

WikidataのQ番号、P625、OSM relation IDの形式が正しくても、別の実体を指していないかを確認する。OSMやCommonsの変更反映には時間差があるため、表示差だけで記事側の誤りと断定しない。

## テンプレート別の確認

### `Maplink2`

- `type`が`point`、`line`、`shape`、`shape-inverse`、`data`のどれか、対象の幾何形状と一致するか。
- `id`または`ids`が意図したQ番号か。省略時に記事自身の項目が使われることを考慮する。
- `coord`とWikidataのP625のどちらが使われるか。手動座標が古いWikidata値を覆っていないか。
- `from`がCommonsの正しい`.map`ページを指すか。
- `frame`、幅、高さ、位置、中心座標、ズームが主題全体を見せるか。切れ、過度な拡大、巨大な固定幅を確認する。
- `text`、`title`、`description`、マーカーが意味を伝えるか。地図だけに本文の重要情報を持たせない。
- 複数機能の番号付き引数で、`type2`、`id2`、`title2`等の組がずれていないか。

テンプレートで利用できないKartographer機能を、未知の引数として無理に指定していないかも確認する。必要なら生の`maplink`または`mapframe`の現行仕様を[MediaWikiのKartographer解説](https://www.mediawiki.org/wiki/Help:Extension:Kartographer)で確認する。

### `Mapriver`

- 記事自身のQ番号を使う場合、第1引数は通常省略できる。別項目を使う指定は理由を確認する。
- P625とP402がそろっているか。河口をたどる表示ではP403、合流先のP31、P402も確認する。
- `zoom`が流路を適切に示すか。
- `mask`の0から7が意図した広域図、詳細図、複合図の表示状態か。
- 河川本体、水系、支流、運河、流域のQ番号やOSM relationを取り違えていないか。

### `Infobox mapframe`

- 標準名前空間で記事自身のデータを使う場合、`id`は通常不要である。別項目の`id`なら理由を確認する。
- P625、P402、P3896の有無と、点・線・面の選択を確認する。
- `coord`でWikidata座標を上書きする場合、上書きの必要性と正確性を確認する。
- 強制中心、座標欠落、geometry欠落、shape link欠落等の追跡カテゴリを確認する。

### `座標一覧`

- `Coord`またはウィキ座標が複数ある記事で、全地点表示が読者に有用か。
- `section`が実在する節を指し、意図した座標だけを集めるか。
- `article`が別ページやリダイレクトを意図的に参照しているか。
- カテゴリでの`level`は探索件数と応答負荷を確認し、過大な範囲を無制限に探索していないか。
- 各座標の`name`が地図上で地点を区別できるか。

## 表示とアクセシビリティ

- 地図のキャプションまたはリンク文が、何を示す地図か説明するか。
- 静的地図やMapframeに利用可能な`alt`がある場合、画像の見た目ではなく地理的意味を伝えるか。
- 色だけで路線、区域、状態を区別していないか。線、ラベル、凡例等を併用する。
- デスクトップ、狭い画面、モバイル、印刷で本文やInfoboxを圧迫しないか。
- 地図を開けない読者でも、本文と表から重要な位置関係を理解できるか。
- 外部のOSM、Commons、Toolforge等が停止しても、記事の主要説明が失われないか。

## エラーと報告

座標エラー、Kartographer、Geoマイクロフォーマット、OSM relation、地図データ等の隠しカテゴリを確認する。追跡カテゴリが示す不足と、実際の誤表示を分ける。

| 項目 | 内容 |
| --- | --- |
| 地図・座標 | テンプレートまたはタグ、主題、表示用途 |
| データ源 | ローカル / Wikidata / OSM / Commons / KML |
| 検証 | 座標、Q番号、プロパティ、relation、`.map`、精度 |
| 表示 | 範囲、ズーム、ラベル、代替説明、モバイル |
| 判定 | 問題なし / 記事側 / 外部データ側 / 共有側 / 未確認 |

別地点や別実体を表示する地図、重要な地理情報を誤解させる座標は`中`以上を検討する。過剰な精度、冗長な`id`、軽微なズームや配置は通常`軽微`とする。
